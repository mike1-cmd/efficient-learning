[English](README.en.md) · 中文

给它一个主题，它按固定六阶带你走：定靶 → 测 → 核心 → 实操 → 图谱 → 回测。
每一步都要落盘产物、过脚本校验，**没过不许进下一阶**。
闭环通过只算「当场会」；要判「已掌握」，还得在至少两个不同日子靠无提示回忆想起来。

> 适用：Claude Code / WorkBuddy / CodeBuddy / 任何支持 `SKILL.md` 的 Agent。
> 零依赖，纯 Python 标准库，数据全在本地。

```
学习环（这一轮怎么学会）
定靶 → ① 测 → ② 核心 → ③ 实操 → ④ 图谱 → ⑤ 回测 → 闭环通过
         ↑                          │                  │
         └──── 答错只回到错的那个概念 ─┘                  │
                                                          ↓
                                            当场会（只证明现在会）
                                                          │
记忆环（学会之后不忘）                                      │
每个概念一条遗忘曲线 → 到期无提示召回 → 想起 → 间隔拉长 ──→ 已掌握
                                    └→ 想不起 → 间隔缩回几天 → 重做那个概念
```

## 为什么不是「让 AI 给我排个 30 天计划」

因为那样做出来的东西，你自己都不会打开第二次。

| 常见做法 | 实际发生了什么 | 这里怎么做 |
| --- | --- | --- |
| 让 AI 生成学习路线 | 一份漂亮目录，看完就结束 | 第 1 阶先做真实任务探底，测出你缺什么，路线才有意义 |
| 一路讲到底 | 讲完 9 个概念，你一个都没动手 | 每个概念必须有一个 5–30 分钟动作，产物路径要被脚本验证存在 |
| AI 替你总结体系 | 图很好看，你脑子里还是散的 | 第 4 阶只给画图规范，你自己画完它才介入纠错 |
| 「懂了吗？」「懂了」 | 流畅感被误判成掌握 | 六种问法轮着考，同一个角度问三遍不算三份证据 |
| 学完就结束 | 两周后归零 | 每个概念按 FSRS-4.5 单独排召回，到期无提示自由回忆 |
| 当天答对就宣布学会 | 只证明还在工作记忆里 | 「已掌握」要求跨天成功提取 ≥2 天 + 稳定度 ≥7 天 |

## 四条硬机制

### 1. 顺序是脚本管的，不是提示词管的

`scripts/stage.py` 是一个状态机。`advance` 会逐项检查当前阶的产物：

- 第 0 阶：目标动作、**可验证的成功标准**、时间预算、交付物 —— 缺一行就拦
- 第 1 阶：真实任务做过 + 「半懂」「空白」各至少 1 条
- 第 2 阶：概念 3–9 个 + 排除清单非空
- 第 3 阶：动作全部勾选 + **每行产物路径真实存在** + 费曼输出已写
- 第 4 阶：自检表填过
- 第 5 阶：最新一轮判满 5 题、对 ≥4、**≥4 题绑定了概念名**

不过就返回非 0，AI 必须把失败项原样告诉你，不许继续往下讲。
成功标准写「熟悉 XX」会被打回，要改成「能独立跑通 X 并交付 Y」。

### 2. 掌握分两档，中间隔着一次睡眠

| 档位 | 判据 | 你能说什么 |
| --- | --- | --- |
| **当场会** | 角度覆盖 ≥4 + 近期正确率 ≥0.75 + 最高通过难度 ≥3 | 「这道题你现在能做对」 |
| **已掌握** | 当场会 + **≥2 个不同日子成功提取** + 稳定度 S ≥7 天 | 「过几天你还想得起来」 |

`report` 会把差距直接写出来：

```
概念          掌握   角度   难度   稳定    想起   状态
闭包          0.66   6/6    4     3.7   100%   当场会（未跨天验证）
             └ 还差：跨天提取 1/2 天、稳定度 3.7/7 天
```

这不是苛刻。同一天答对四道题，只证明东西还在工作记忆里——补习班刷一天题第二天归零，就是这个原因。

### 3. 每个概念一条自己的遗忘曲线

不用 D+1 / D+3 / D+7 / D+14。固定节奏对难概念太短（每次都在快忘光时复习，等于每次重学），对易概念太长（明明记得住却被反复打扰）。

这里用 FSRS-4.5 同族算法，每个概念独立维护：

- **S（稳定度，天）**：这次记忆能撑多久
- **D（难度，1–10）**：这个概念对你有多难

间隔由公式算，不是模型心算的。同一天答对的两个概念，一个 S=3.7 天、一个 S=49 天，下次出现时间就该差十倍。

**同一天同一概念的第二条记录起只算练习，不动 S/D** —— 一份证据不能算两遍，否则间隔会被虚抬成「今天练了三遍，三周后再来」。

### 4. 出题与判分分开记账，并且自我对账

`coach.py next` 决定下一个问什么：五类取题桶（**到期 > 续做 > 补弱 > 练熟 > 新概念**）、
六个角度（定义 / 边界 / 反例 / 操作 / 关系 / 迁移）、五档难度（认得出 → 造得出）。

难度用 1PL IRT 反解，目标做对率卡在 **70%–85%** —— 太简单是浪费时间，太难过是制造挫败。

然后它会给一个 `p_expected`。这个数字是要被核对的：

```bash
python scripts/coach.py calibration <会话>          # Brier 分数 + 分档表
python scripts/coach.py calibration <会话> --apply   # 把系统性偏差写回个人模型
```

预测七成把握、实际只有五成通过，就说明这个「七成」是假的，难度要整体降一档。
样本 <5 条返回 2 并说明「还没法测」——**测不了不等于测得准**。

同样的对账也发生在遗忘曲线上（`p_recall` vs 实际结果），两套预测分别算分，不混在一起。

## 快速开始

**需要**：Python 3.10+（脚本用了 3.10 的联合类型写法），无需 `pip install` 任何东西。

### 装成技能

```bash
git clone https://github.com/mike1-cmd/efficient-learning.git
cp -r efficient-learning ~/.workbuddy/skills/efficient-learning
```

Claude Code 用户放到 `~/.claude/skills/efficient-learning`；
项目级共享放到 `<项目>/.workbuddy/skills/`。

或者让 AI 自己装：把仓库目录拖进对话框，说「装到我的用户技能目录」。

装完**新开一个对话**（已开着的会话读不到新技能），说：

> 我要学 XX

触发成功的第一句一定是：

```
【第 0 阶 · 定靶】
```

没出现这行，说明技能没加载上。

### 建一个学习会话

```bash
python scripts/new_session.py "闭包" --path ./learn
cd learn/2026-11-17-闭包
```

生成五份文件（`00-plan.md` … `04-knowledge-map.md`）+ `.stage.json`，全部从模板生成。

## 一局完整的样子

```bash
# 每天第一件事：只给一个动作
$ python scripts/coach.py today .

【今天】2026-11-17　连续第 5 天

到期召回   3 个（约 9 分钟）
补弱       1 个（闭包：最近答对率 33%）
可开新概念 2 个（词法作用域、延迟绑定）

⚠ 你已经在学「闭包」，但它依赖「词法作用域」还没编码 ——
  现在能答对，多半是靠背下来的，换个场景就会断。

现在做这一件：召回「闭包」（63% 还记得，拖到明天约 45%）
  coach.py recall ./learn/2026-11-10-闭包
```

```bash
# 出题：给桶、角度、难度、理由
$ python scripts/coach.py next .

【取题】补弱 · 闭包
角度    边界　← 刚在这个角度答错，先补到过关再换角度
难度    3/5（预计做对率 78%，目标带 70%–85%）
理由    最近答对率 33%
```

```bash
# 召回：只给概念名，限时四步自由回忆
$ python scripts/coach.py recall .

【召回 1/3】闭包　现在还能想起的概率 63%
逾期 2 天，已经忘过 1 次

规则：不看书、不翻笔记、不问我。先讲，讲完再对。
限时 90 秒，按这四步讲：
  1. 是什么：一句话说清它是什么。不许用这个词自己解释自己。
  2. 什么时候失效：什么情况下它会失效、不成立，或者你会用错。
  3. 举个例子：举一个你自己写过的例子；没有就现编一个真实场景。
  4. 和谁有关：它和「词法作用域」是什么关系，谁决定谁。
```

**答之前不给评分标准** —— 标准本身就是提示。`--json` 才把 rubric 给出来，给 AI 判分用，不能念给用户。

```bash
# 答完立刻记账（写日志 + 更新遗忘曲线 + 抄进跨主题档案）
$ python scripts/coach.py record . --concept "闭包" --grade 对 --angle 边界 \
    --level 3 --seconds 42 --confidence 4 --evidence "他说：函数记住了定义时的作用域"
```

## 命令速查

| 命令 | 什么时候用 | 它做什么 |
| --- | --- | --- |
| `stage.py status <会话>` | 随时 | 我在哪一阶、还差什么、今天该做什么 |
| `stage.py check <会话>` | 进阶前 | 只校验，不改状态 |
| `stage.py advance <会话>` | 校验通过后 | +1 阶；过第 5 阶时把结论写成收据排进复习 |
| `stage.py retry <会话> --concept "闭包"` | 回测答错 | 退回第 3 阶只重做这一个概念，动作行取消勾选、清空产物；同时给记忆模型记一次遗忘 |
| `stage.py reset <会话> --reason "..."` | 同概念连错 2 轮 | 归档旧轮到 `archive/roundN/`，回第 0 阶重定靶 |
| `stage.py due <会话> [--cap 5]` | 看复习队列 | 今天到期，忘得最多的排前面；`--all` 合并同目录所有主题 |
| `stage.py grade <会话> --concept ... --grade 对` | 复习后 | 记分；`--evidence` 存原话 |
| `stage.py stats <会话>` | 每周 | 实测留存率 / 校准偏差 / **凭证率** / 反复遗忘榜 |
| `coach.py today <会话>` | 每天第一件事 | 只给一个动作，不给菜单 |
| `coach.py next <会话> [--json]` | 出题前 | 桶 / 概念 / 角度 / 难度 / 理由 |
| `coach.py recall <会话> [--json]` | 有到期时 | 无提示召回，限时四步 |
| `coach.py add <会话> --concept ... --stem ... --rubric ...` | 出完题 | 存进题库，下次不重复 |
| `coach.py record <会话> --concept ... --grade ... --evidence ...` | 答完 | 三处同时记账 |
| `coach.py sync <会话>` | 第 5 阶收尾 | 把本轮答题写进回测表，否则卡门禁 |
| `coach.py report <会话>` | 想知道进度 | 两级状态 + 角度覆盖 + 还差什么 |
| `coach.py profile <学习根>` | 换主题前 | 你在哪种问法下最容易错、卡在哪档难度、高估自己多少 |
| `coach.py calibration <会话> [--apply]` | 每答五题 | 难度模型 + 遗忘曲线双模型对账 |

评分四档：`错` / `勉强` / `对` / `轻松`。
只填「对/错」也能跑，但「勉强对」和「轻松对」不该拿到同样间隔。

**流畅度也是判据**：答对但用时超过该概念自己中位数 2.5 倍，按「勉强」计入。
45 秒才想起一个 12 秒该反应过来的东西，考试超时、现场答不上来，结果一样。

## 数据长什么样

全在本地，人可读，没有云端、没有账号：

| 文件 | 内容 |
| --- | --- |
| `.stage.json` | 阶段状态、轮次、降级与回路留痕 |
| `.learning.json` | 每个概念一条遗忘曲线（S / D / 复习次数 / 遗忘次数 / 别名） |
| `.items.json` | 题库（题面 / 角度 / 难度 / 评分标准 / 出过几次） |
| `.attempts.jsonl` | 每次答题原始记录，只追加。含 `p_expected` / `p_recall` 两个预测 |
| `_coach/events.jsonl` | 跨主题学员档案，只追加 |
| `_coach/model.json` | 个人校准参数（难度偏移 / 留存偏移 / 拟合样本量） |

换一个主题学，`profile` 还记得你上次的毛病：
某个角度历史正确率 <50%（样本 ≥3），新概念的六个角度里就优先问它。

## 设计取舍

**为什么用脚本而不是全交给模型判断？**
纯提示词的 skill 会稳定地漂移：今天严明天松、说好五阶结果跳到三阶。把「有没有产物」「概念名填没填」「路径存不存在」这类机械判断交给脚本，模型只负责它真正擅长的部分——出题、判分语义、追问。

**为什么脚本不判断「学得对不对」？**
判不了。`stage.py` 只判有没有实质内容：字段填了没、动作勾了没、路径存在吗。
内容正确性由 AI 复核。**绿灯不等于学会**——这一点写在 SKILL.md 里，也写在每个已知边界里。

**为什么答错要改遗忘曲线？**
答错是这个系统能拿到的最强信号。只退流程不改曲线，等于承认他忘了却假装没忘。

**为什么要求 `--evidence` 存用户原话？**
出题和判分是同一个模型，换上下文盲评目前只是文件里的纪律，不是机制。
原话是唯一的硬凭证——它把用户说的话钉在事件里，事后可复查判分有没有曲解。
`stats` 单列「凭证率」，低于 50% 说明判分在靠印象，等于给自己发合格证。

**为什么不用向量库 / 云同步？**
一个学习会话就 6 个文件，几千条记录。JSON 够用，而且人可以直接打开看、可以 git diff、可以手工改。引入数据库只会让它更难被信任。

---

## 已知边界

- **判分仍由同一个模型完成。** 「换新上下文盲评」是纪律，不是强制。`--evidence` 是补偿手段，不是根治。
- **只校准全局难度偏移。** `BETA_STEP` 和 70–85% 目标带还是先验，不是从你的数据里学出来的。
- **弱角度偏置只在「没测过的角度」生效。** 已经测过的角度不会被强行重排。
- **需要 Python。** 没有 Python 的环境里六阶会退化成提示词约束，硬门禁失效。
- **中文优先。** 脚本的列宽对齐、术语、提示都按中文调过；英文能用，但没专门优化。
